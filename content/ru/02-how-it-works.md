# 2. Как это работает, шаг за шагом {#ru-steps}

## Простыми словами

Инструмент отвечает на восемь вопросов в фиксированном порядке, и у каждого вопроса свой модуль. `pipeline.py` только вызывает их один за другим; другой логики в нём нет. Если нужно понять, где что происходит, вопрос подсказывает файл.

![Внутри ассистента: восемь шагов, у каждого свой модуль.](images/core.ru.png)

## Восемь шагов

1. **Что изменилось?** `changed_files.py` выполняет `git diff` относительно базовой ветки и оставляет только прод-файлы Python: без тестов, без сгенерированных файлов, без исключённых папок. Для каждого файла запоминает, какие строки изменились.
2. **В каком порядке?** `import_graph.py` смотрит на импорты между изменёнными файлами и сортирует их так, чтобы модуль обрабатывался раньше файлов, которые его импортируют. Алгоритм объяснён в разделе 10.
3. **Что тестировать?** `test_targets.py` разбирает каждый файл модулем `ast` (ничего не исполняется) и выбирает публичные функции и методы, строки которых изменились. Если файл новый, целью становится каждая публичная функция.
4. **Какие тесты уже есть?** `test_finder.py` ищет связанные тест-файлы: `tests/test_<имя>.py`, зеркальную структуру папок или любой тест, где упоминается модуль или его функции. Собственные сгенерированные тесты инструмента никогда не считаются.
5. **Запрос к Gemini.** `prompts.py` собирает промпт, `llm_client.py` отправляет его. При temperature 0 один и тот же промпт даёт один и тот же ответ, поэтому кэш (`cache.py`) отдаёт повторы бесплатно.
6. **Тесты проходят?** `test_generator.py` записывает ответ в `tests/generated/`, запускает на нём pytest и при падении просит починить, не больше двух раз. `llm_test_code.py` перед этим очищает и проверяет каждый ответ.
7. **Старые тесты устарели?** `suggested_updates.py` просит новую версию каждого связанного тест-файла и записывает её в `reports/suggested-tests/`. Оригинал не трогается.
8. **Что получилось?** `report.py` пишет `ai-test-report.md` для людей и `ai-test-report.json` для машин.

## Карта модулей

```
ai_test_assistant/
  cli.py                   3 команды → pipeline
  config.py                умолчания → yml → env → флаги
  pipeline.py              вызывает шаги 1–8 по порядку, и только
  changed_files.py      1  git diff → изменённые файлы и строки
  import_graph.py       2  топологический порядок (Кан)
  test_targets.py       3  публичный код, задетый диффом
  test_finder.py        4  связанные существующие тесты
  prompts.py            5  три промпта
  llm_client.py         5  вызов Gemini, dry-run, кэш
  cache.py              5  LRU + LFU, написаны с нуля
  llm_test_code.py      6  запрос → очистка → проверка → запись
  test_generator.py     6  генерация → pytest → починка
  pytest_runner.py      6  pytest в подпроцессе
  suggested_updates.py  7  новые версии связанных тестов
  report.py             8  Markdown + JSON
  models.py                данные, которые шаги передают дальше
  repo_paths.py            правила путей, общие для всех шагов
```

## Четыре правила, которым следует код

- **Один модуль — одна задача — одно имя.** Каждый файл отвечает на один вопрос потока, и имя говорит, на какой. Файлов `utils` и `helpers` нет.
- **Зависимости направлены в одну сторону.** Внизу `models` и `repo_paths`, над ними восемь модулей-шагов, сверху `pipeline`, над ним `cli`. Циклов нет; ни один шаг не импортирует другой шаг.
- **Обычные функции.** Ничего не выполняется параллельно, поэтому нет `async`. PR обрабатывается файл за файлом, и один сломанный файл не останавливает остальные: его ошибка попадает в отчёт.
- **Решает человек.** Результат записывается в файлы; коммит — решение человека.

## Вероятные вопросы

**Q:** Почему файлы обрабатываются по очереди, а не параллельно?

**A:** Каждый файл — один-два вызова LLM и запуск pytest. Типичный PR меняет несколько файлов, так что весь запуск занимает пару минут в любом случае, а последовательный код куда проще читать и отлаживать. Облачный режим масштабируется числом воркеров, а не потоков.

**Q:** Что дают «изменённые строки»?

**A:** Фокус. Если в файле двадцать публичных функций и одна изменена, тесты получает только она. Ревьюер видит маленький релевантный тест-файл вместо большого общего.

**Q:** А если в изменённом файле синтаксическая ошибка?

**A:** Шаг 3 не сможет его разобрать, файл попадёт в отчёт со статусом `error` и сообщением, а запуск продолжится со следующим файлом.
