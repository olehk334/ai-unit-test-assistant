# 3. Где это работает {#ru-where}

## Простыми словами

Восемь шагов — это библиотека. Вызвать её могут три разных источника: разработчик в терминале, workflow GitHub Actions и облачный сервис. Библиотека не знает, кто её вызывает. Различаются только запуск и место, куда уходит результат.

![Одно и то же ядро работает в трёх местах.](images/two-ways.ru.png)

## Три точки входа

| Точка входа | Команда или событие | Для чего |
| --- | --- | --- |
| Терминал | `ai-test-assistant run-pr-assistant --base-ref origin/main` | попробовать на своей ветке; `--dry-run` работает без доступа к облаку |
| GitHub Actions | pull request, меняющий `.py`-файлы | один репозиторий; никакой инфраструктуры |
| Google Cloud | webhook от GitHub | много репозиториев; один общий сервис с метриками |

Команда для одного файла, `ai-test-assistant generate-tests --source path/to/file.py`, выполняет те же шаги для одного файла и пишет только сгенерированные тесты, без предложений.

## Одна конфигурация, четыре слоя

Настройки приходят из четырёх мест, каждое следующее перекрывает предыдущее: встроенные умолчания, `ai-test-assistant.yml` в репозитории, переменные окружения с теми же именами в верхнем регистре (`DRY_RUN`, `GEMINI_MODEL`) и флаги командной строки. Файл `.env` в репозитории сначала загружается в окружение. Облачный воркер задаёт `DRY_RUN` или `GEMINI_MODEL` через окружение, CLI — через флаги; оба читают один загрузчик.

## Почему три способа

Терминал — для разработчика, который хочет увидеть, что делает инструмент, прежде чем ему доверять. GitHub Actions — самый дешёвый способ встроить его в процесс команды: один YAML-файл, никаких серверов. Облачный сервис нужен компании с многими репозиториями: одно место, которое обслуживает все, с очередью, повторами и дашбордом. Этот режим описан в разделах 8 и 9.

## Вероятные вопросы

**Q:** Дают ли три режима разные результаты?

**A:** Нет. Все вызывают одну и ту же функцию `run_pr_assistant`. Сквозные тесты фиксируют отчёт, имена файлов и порядок, так что изменение, сломавшее один режим, сломало бы тесты всех трёх.

**Q:** Как запустить без аккаунта Google Cloud?

**A:** С `--dry-run`. LLM заменяется фиксированным тестом-заглушкой, а всё остальное (git, разбор, pytest, отчёты) работает по-настоящему. Именно так работают 103 собственных теста проекта.
